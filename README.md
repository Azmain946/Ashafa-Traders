# Ashafa Traders — Pharmacy ERP

A complete pharmacy ERP built as a **single Django 5 monolith**. It covers
homepage, search, cart/checkout, customer directory, invoices, products and
stock, dashboard, reminders, returns, antibiotic register, suppliers and
settings — all in one project, one database, one deployment unit.

## Stack

| Concern        | Choice                                       |
|----------------|----------------------------------------------|
| Backend        | Django 5.x (Python 3.12+)                    |
| Frontend       | Django templates + Bootstrap 5.3             |
| Interactions   | Vanilla JS + jQuery (only for AJAX/DOM bits) |
| Charts         | Chart.js (loaded only on dashboard)          |
| DB             | SQLite for local dev, PostgreSQL for prod    |
| Images         | Pillow (auto WebP optimisation + thumbnails) |
| Static serving | WhiteNoise                                   |

No React, Vue, Angular, or other JS frameworks. No microservices.

## Project layout

```
config/                 # Django project settings + URL conf
apps/
  core/                 # Shared models (AppSetting, ActivityLog), utils, imaging
  accounts/             # Auth, UserProfile, settings page, staff users
  inventory/            # Products, Categories, Manufacturers, Batches, Stock
  customers/            # Customer directory + history
  suppliers/            # Suppliers, purchase invoices, uploaded receipts/memos
  sales/                # Cart, checkout, invoices, returns, antibiotic register
  dashboard/            # Home + metrics dashboard
templates/              # Base layout, partials, page templates per app
static/
  css/                  # theme.css, print.css
  js/                   # app.js, order.js
  img/                  # favicon, assets
  vendor/               # Bootstrap, Bootstrap Icons, jQuery
media/                  # Uploads (products, receipts, branding, avatars)
```

## Quick start (local dev)

```bash
# 1. Install
python3 -m pip install --user -r requirements.txt

# 2. (Optional) Copy and edit env
cp .env.example .env

# 3. Migrate and seed demo data
python3 manage.py migrate
python3 manage.py seed_demo            # creates admin/admin12345 + sample data

# 4. Run
python3 manage.py runserver 0.0.0.0:8000
```

Sign in at `http://localhost:8000/accounts/login/` with **admin / admin12345**.

## Configuration

All configuration is read from environment variables (see `.env.example`):

- `DJANGO_SECRET_KEY` — required for production.
- `DJANGO_DEBUG` — `True` / `False`.
- `DJANGO_ALLOWED_HOSTS` — comma-separated.
- `DATABASE_URL` — set to a `postgres://…` URL in production; leave empty to use
  the bundled SQLite database during development.
- `BUSINESS_NAME` — initial business name shown until you update settings.

Business-level settings (currency, invoice prefix, low-stock thresholds,
near-expiry window, logo) are edited from the in-app **Settings → Business** tab.

## Architectural notes

### Database

- Models are normalised, with FK relations between products → batches → stock
  movements, and between invoices → items → batches.
- Indexes exist on common search fields (product name, generic, barcode, batch
  number, invoice number, invoice date).
- Stock changes are recorded through `apps.inventory.services.adjust_stock`,
  which uses `SELECT FOR UPDATE` and refuses to let stock go negative.
- Invoice numbers are generated by `InvoiceSequence` with row-level locking
  inside `next_invoice_number`, guaranteeing uniqueness even under concurrent
  checkouts.

### Cart / checkout

- Cart state lives in the user's session (server-side).
- AJAX endpoints under `/sales/cart/*` add, update, remove, clear, and summarise
  cart contents.
- `apps.sales.services.checkout` runs in a single atomic transaction:
  - locks all involved batches,
  - validates expiry + stock,
  - creates invoice + items,
  - decrements stock via `StockMovement` records,
  - inserts antibiotic register entries for ABX products,
  - generates a unique invoice number.

### Images

- Product images are validated, EXIF-stripped, resized within `1200×1200`,
  converted to WebP, and stored with a UUID filename. A square `300×300` thumb
  is generated for cards and search suggestions.
- Receipts/memos accept JPG, PNG, WebP and PDF up to 10 MB and are stored under
  `media/receipts/` with UUID filenames.

### Performance

- Live search uses 2-character minimum + ~220 ms debounce on the client.
- List views paginate (24 products/page, 25 invoices/page, etc).
- Querysets use `select_related` / `prefetch_related` and aggregate functions to
  avoid N+1 queries.
- Stock and invoice counters use SQL `SUM` / `COUNT` aggregations.

### Security

- All forms (including AJAX) require Django's CSRF token.
- Admin-only settings sections are gated by `_is_admin` (superuser or `admin`
  role).
- Uploaded files are validated for extension and size.
- `whitenoise` serves compressed, fingerprinted static assets in production.
- HSTS, secure cookies and other hardening enabled when `DEBUG=False`.

## Deployment notes (brief)

- Set `DJANGO_DEBUG=False`, `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`, and
  `DATABASE_URL` (PostgreSQL).
- Run `python manage.py collectstatic --noinput`.
- Serve with `gunicorn config.wsgi:application` behind a reverse proxy.
- Mount `media/` and `staticfiles/` to a persistent volume (or move to S3-style
  storage if needed).
